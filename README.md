# 🎬 Watch2gether: Синхронный просмотр видео (Redis + WebSockets)

Курсовой проект, представляющий собой веб-приложение для синхронного просмотра видео разными пользователями в режиме реального времени. 

Синхронизация состояний плеера (Play/Pause/Seek) между клиентами реализована через **Redis Pub/Sub**, а сохранение актуальной позиции видео — через **Redis Hash**.


## 🚀 Особенности проекта

* **Синхронизация в реальном времени:** задержка между устройствами минимальна благодаря WebSocket.
* **Хранение состояния:** если новый зритель подключается к комнате, его видео автоматически перематывается на ту секунду, на которой остановились остальные (состояние хранится в Redis).
* **Архитектура Pub/Sub:** сервер не хранит подключения в памяти для рассылки, а использует Redis как единую шину событий. Это позволяет легко масштабировать сервер (запускать несколько экземпляров).
* **Работа по локальной сети:** сервер доступен для других устройств (телефонов, ноутбуков) по IP-адресу в одной Wi-Fi сети.

## 🛠️ Технологический стек

* **Backend:** Python 3.9+, `websockets` (асинхронный WebSocket-сервер), `redis.asyncio` (асинхронный клиент Redis).
* **База данных / Брокер сообщений:** Redis.
* **Frontend:** HTML5, CSS3, Vanilla JavaScript (нативный `<video>` API, WebSocket API).
* **Среда разработки:** PyCharm.

## ⚙️ Установка и запуск

### 1. Подготовка окружения
Вам понадобится установленный **Python 3.9+** и **Redis** (локально или через Docker).

Сначала клонируйте репозиторий:
    git clone https://github.com/ваш-никнейм/watch2gether.git
    cd watch2gether

Затем создайте виртуальное окружение и активируйте его:
    python -m venv .venv

Для Linux/MacOS:
    source .venv/bin/activate

Для Windows (PowerShell):
    .venv\Scripts\activate

Установите зависимости:
    pip install -r requirements.txt

### 2. Запуск Redis
* **Windows:** скачайте и запустите `redis-server.exe` (или используйте WSL).
* **Docker:** `docker run -d -p 6379:6379 redis`
* **Linux/MacOS:** `redis-server`

### 3. Запуск серверов
Проект состоит из двух серверов: WebSocket (для синхронизации) и HTTP (для раздачи HTML-файла). Запустите их в **двух разных терминалах**.

**Терминал 1 — WebSocket-сервер:**
    python server.py
*Сервер запустится на `ws://0.0.0.0:8765`*

**Терминал 2 — HTTP-сервер (раздача клиента):**
    python -m http.server 8080
*Клиент будет доступен по адресу `http://localhost:8080/client.html`*

### 4. Как проверить синхронизацию
1. Откройте `http://localhost:8080/client.html` в двух вкладках браузера (или на двух разных устройствах в одной сети).
2. Нажмите кнопку **«Подключиться»** в обеих вкладках.
3. Нажмите **Play** в первой вкладке — вторая должна начать воспроизведение с той же секунды.
4. Нажмите **Pause** во второй — первая тоже остановится.
5. Обновите страницу во второй вкладке — видео автоматически перемотается на актуальную позицию (благодаря чтению из Redis).

## 🌐 Запуск в локальной сети (на разных устройствах)

Чтобы открыть проект на телефоне или другом компьютере:

1. Узнайте IP-адрес вашего компьютера в локальной сети (в Windows: `ipconfig` → «IPv4-адрес», например `192.168.1.10`).
2. В файле `client.html` измените адрес WebSocket. Вместо:
    const wsUrl = `ws://localhost:8765/${room}`;
Укажите свой IP:
    const wsUrl = `ws://192.168.1.10:8765/${room}`;
3. В файле `server.py` убедитесь, что сервер слушает все интерфейсы: `HOST = "0.0.0.0"`
4. Разрешите порты **8080** и **8765** в брандмауэре Windows (создайте правила для входящих подключений).
5. На другом устройстве откройте `http://192.168.1.10:8080/client.html`.

## 🧠 Архитектура синхронизации

1. **Хранение состояния (Redis Hash):** 
   Когда пользователь ставит видео на паузу или перематывает, сервер сохраняет текущую секунду в ключ `room:{id}:state`. Когда новый пользователь подключается, сервер отправляет ему начальное событие `init` с прочитанной позицией.
2. **Мгновенная рассылка (Redis Pub/Sub):** 
   При любом действии сервер публикует сообщение в канал `room:{id}:sync`. Отдельный асинхронный слушатель на сервере читает этот канал и рассылает событие всем подключённым WebSocket-клиентам комнаты.
3. **Защита от «эха»:** 
   В сообщениях передаётся идентификатор отправителя (`sender`), чтобы клиент игнорировал события, которые он сам же и инициировал, предотвращая зацикливание.
